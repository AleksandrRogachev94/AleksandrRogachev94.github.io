# art/

Everything here is **authored** — it came from a generator or a hand, and no script can
recreate it. Nothing here is loaded by the site; `public/art/` holds what ships.

```
room-day-summer.jpg    the master. Untouched generator output, never edited in place.
hotspots.json          SAM prompts for the CLICKABLE objects. Splat build; see below.
objects.json           what hides what, plus normalised SAM prompts and depth ops.
masks-manual/          masks SAM could not win — generated or painted, then committed.
fills/                 hand-made plates for holes LaMa cannot fill. Often absent.
room-day-summer.ply    GITIGNORED. SHARP's reconstruction; see below.
build/                 GITIGNORED. Everything the tools derive from the above.
```

`rm -rf build` is always safe. It is regenerated by one run of the chain in
[docs/SCENE.md](../docs/SCENE.md), which is also the only place the exact commands live.
The line is drawn there deliberately: if a file can be remade by running the chain it goes
in `build/`, and then "is this worth committing?" never has to be answered again.

## The `.ply`, and why it is not committed

`room-day-summer.ply` is Apple SHARP's Gaussian reconstruction of the master — 63MB, and
the input to `tools/sharp_splat_bake.py`, which writes the four rasters the site actually
loads into `public/art/`. **Those are committed; the PLY is not.** It is a tool output
rather than an authored input, and 63MB of it in history would be paid for on every clone
and every CI checkout of a repo that deploys to GitHub Pages.

The honest caveat: unlike everything in `build/`, this one is **not cheaply regenerable**.
SHARP's weights are research-only and it wants a GPU. So keep a copy somewhere outside
git — losing it means the bake cannot be re-run from the master alone, even though the
site would keep working from the committed rasters. If it is ever regenerated, the numbers
in `src/data/scene.ts` (`nearZ`, `farZ`, `fovDeg`) come straight out of the bake's manifest
and must be copied across with it.

## Two prompt files, two questions

`objects.json` answers *what hides what* — the LAYERED build's occlusion graph, which
needs `in_front_of`, SAM masks for sixteen objects, and LaMa fills behind each. The splat
build asks none of that: it has no layers, nothing to inpaint and no plates to cut.

`hotspots.json` answers *what is clickable*, which is unrelated and much smaller. The only
surviving use for a mask in the splat build is the hotspot — `tools/wake.py` bakes the
object's own light from it, and its bounding box is the tap target in
`src/data/hotspots.ts`. Three objects, not sixteen, and `tools/pick.py --mask-dir` cuts
them interactively so `segment.py` never runs.

The day image is the geometry lock. Every other variant is an *edit* of a locked master,
because edits register pixel-for-pixel and fresh generations drift. Regenerate from
[docs/PROMPTS.md](../docs/PROMPTS.md), never from memory; that file also carries the
naming convention and the full asset ladder.

## Depth maps

`build/<name>-depth.png` comes from `tools/depth.py` (stage 0) — Depth Anything V2-Large,
run locally. Three things about the format matter downstream:

- **It is disparity, not distance.** Near is a *high* value, far is *low*. Anything that
  displaces a mesh with it wants near-is-high, so no inversion is needed — but do not
  assume the opposite when reading it.
- **It is relative and un-normalised.** The values occupy a narrow slice of the 16-bit
  range (the HF demo space this used to come from returned 12–376 of 65535; `depth.py`
  rescales to the full range itself). **Always rescale by the image's own min/max** before
  using or exporting it. Treating the raw values as 0–65535 yields a nearly flat map.
- **Same pixel dimensions as its colour image**, always.

The 16-bit map is the archive. The **8-bit rescaled version is the working format** —
browsers truncate texture uploads to 8 bits anyway, and LaMa takes 8-bit input — so the
layer and inpainting stages all operate on it. `public/art/*-depth.webp` is that 8-bit
export; WebP cannot carry 16 bits.

Both live in `build/` and are regenerable, so neither is committed. The 16-bit map is the
one worth keeping across a model upgrade if you ever want to freeze geometry against a
newer Depth Anything — copy it out of `build/` deliberately if that day comes.
