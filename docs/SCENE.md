# Making a scene

Start to finish, for a new master. The reasoning behind every step is in
[PIPELINE.md](PIPELINE.md) — read that when something looks wrong, not before.

## Once, ever

```sh
python3 -m venv tools/.venv
tools/.venv/bin/pip install -r tools/requirements.txt
tools/.venv/bin/pip install --no-deps simple-lama-inpainting==0.1.2
```

**Two commands, and the second one needs `--no-deps`** — LaMa's package pins a Pillow old
enough that it will not build on Python 3.13, and everything it actually imports is
already in `requirements.txt`. That is why it is not in the file: pip has no
per-requirement `--no-deps`.

Weights download themselves on first use (~4 GB total, cached in `~/.cache/huggingface`):
Depth Anything V2 for depth, SAM 2.1 for masks and ViTMatte for see-through boundaries
(all three through `transformers`), and LaMa for the fills (through
`simple_lama_inpainting`).

None of this is a site dependency. `tools/` never enters `package.json`; the browser
loads plain images.

## 1. Put the master in place

`art/<name>.jpg`, straight from the generator, never edited. Prompts are in
[PROMPTS.md](PROMPTS.md). Then:

```sh
NAME=<name>
S=art/$NAME           # authored: the master, $S.jpg
B=art/build/$NAME     # derived:  everything the tools write
mkdir -p art/build/masks
```

Everything below uses `$S` for the one file you were given and `$B` for everything made
from it. **`art/build/` is gitignored and disposable** — deleting it costs one re-run of
stage 3 and nothing else. `art/` keeps exactly four authored things:

| | |
| --- | --- |
| `art/<name>.jpg` | the master. The geometry lock; every variant is an *edit* of it. |
| `art/objects.json` | what hides what, plus normalised click prompts and depth ops. |
| `art/masks-manual/` | masks SAM could not win, painted or generated by hand. |
| `art/fills/` | hand-made plates for holes LaMa cannot fill. Often empty. |

Nothing in `art/` is loaded by the site. The site reads `public/art/` only.

## 2. Say what hides what

`art/objects.json` is the one hand-authored file in the pipeline. Everything else is
derived from it and the master.

### Which objects earn an entry

Only two things earn one, and they are independent:

1. **It hides something.** There is surface behind its silhouette, at a clearly different
   distance, that the camera will uncover when it slides. That surface has to be painted
   in, which means this object has to be cut off the thing behind it.
2. **Its depth is semantically wrong.** The outline is right and only the number is wrong,
   so no amount of segmentation can fix it — the office chair comes back at the same
   distance as the desk it sits in front of. That earns an `op`, and may not need a layer.

If neither is true, leave it out. Ask one question and the answer falls out:

> **slide the camera a few percent sideways — does anything appear from behind this?**

The poster is flat on the wall: nothing appears, no entry. The keyboard lies on the desk:
the only thing behind it is the desk, and the desk moves with it, so nothing appears — no
entry. The 3D printer stands off the cabinet against a bright window: floor, cabinet top
and window all appear — entry.

Two practical thresholds, because the camera travel is small:

- **Depth gap.** If the object and what is behind it differ by less than ~0.05 in the 0–1
  depth map, the parallax between them is under a pixel. Not worth a layer.
- **Size.** A silhouette a few pixels wide reveals a few pixels of background. The
  inpainter will handle it invisibly as part of the layer it sits in.

Fifteen entries is about right for a room like this one. Every entry is a mask you own
forever, so the bar is "hides something worth painting", not "is a nameable object".

### What goes inside one mask

This is the part that feels ambiguous and is not. **A mask is a group of pixels that move
together.** So:

**Everything lying flat on a surface belongs to that surface's mask.** Keyboard, mouse,
mousepad, papers, an under-desk keyboard tray — they are at the desk's depth, the desk is
what is behind them, and the desk carries them. Drag the box round the *whole desk
including all of it* and do not try to exclude them. Excluding the keyboard is actively
wrong: it would stay pinned to the wall while the desk slides out from under it.

**Everything standing up off a surface gets its own entry**, because there is wall or
window behind it at a very different distance. Monitors, the desk lamp, the printer and
speaker on the cabinet. These get `in_front_of: ["desk"]` and draw in a nearer layer.

The dividing line is not "is it a separate object", it is **height above the surface** —
but height still has to buy a depth gap, so check before you add an entry. On this master
the mug rises well above the desk's back edge and is silhouetted against the wall, and it
still does not earn one: it reads 85 against 79 behind it, a gap of 6 where the threshold
is ~13. The headphones read 92 against 94 — behind their own surround. A `desk-clutter`
entry was seeded for exactly those two and deleted once measured. **Measure the gap; do
not reason from the geometry.**

### Picking it

Start the file from nothing:

```json
{ "objects": [] }
```

then add each object in `pick.py` with the **+ new** button — it asks for a name and what
the object is in front of. Existing objects reopen from the dropdown for re-picking.

```sh
tools/.venv/bin/python tools/pick.py --color $S.jpg --objects art/objects.json
# http://localhost:8765
```

| | |
| --- | --- |
| **drag a box** | **the strongest prompt — start here for anything large or cluttered** |
| left click | this **is** the object |
| right click / shift-click | this is **not** it — use these to fence off neighbours |
| **see-through** checkbox | tick for plants, open frames, wire racks — anything you can see the room *through*. Untick for solid objects. |
| `u` / `c` | undo one point / clear all |
| `s` | save this object into objects.json |
| drop box | remove the box, keep the points |

**Use a box for furniture.** Points are the wrong tool for a big object covered in other
things. On the desk — a sunlit slab under a keyboard, a mouse, headphones and a mug, one
leg behind the chair — seven positive points and three negatives score 0.739 and lose the
left leg entirely; **the bounding box alone scores 0.862 and takes the slab and both
legs.** Drag the box round the whole object, then add negative clicks only for things the
box swallows that should not be in it. Points on their own are for small objects and for
carving one thing out of a group.

**Order matters, slightly.** Author the thing that is hidden before the thing that hides
it, so `in_front_of` always names something already in the file — cabinet before the
printer standing on it.

### When SAM cannot do it — paint the mask

Some objects are not winnable by prompting, and recognising one early is worth more than
another hour of clicking. The desk is the standing case: a slab under a keyboard, a mouse,
headphones and a mug, with an epoxy river down its length that SAM reads as a separate
object, and a live edge that no box follows. Points, boxes and polygons were all tried on
it, and each left stranded islands somewhere.

A stranded island shears. `inpaint.py` rewrites the shell's **depth** inside the hole, so a
patch of desk left out of the desk mask keeps the desk's disparity while everything around
it is filled with the floor's — measured on this master, about 89 against 80, or 5% of the
frame's parallax range. Not catastrophic, but it is a slow shear across a surface that
should be rigid, and it costs nothing to avoid. **Completeness matters more than a
beautiful boundary**, which is the opposite of what prompting optimises for.

**Ask the generator for the mask before you paint one.** Prompt MASK in
[PROMPTS.md](PROMPTS.md) asks Gemini to turn the master into a white-on-black mask of one
object. On the desk it beat SAM outright and beat what a hand would trace: it followed the
live edge of the wood, went up and around the mug and the headphones where they break the
back-edge silhouette, threaded between both monitor stands, traced the cables hanging under
the top, and stopped cleanly at the chair. Two properties make it usable rather than a toy:

- **It returns at a fraction of the master's size** — 1376x768 for a 5504x3072 master, an
  exact 1/4. Upscale and threshold; the 4px edge quantisation that leaves is 0.07% of frame
  width and invisible next to what it gets right.
- **It excludes flat things lying on the surface**, however firmly the prompt says to
  include them. Mouse and mouse pad came back as enclosed holes, which `fill_holes` closes
  for free. The keyboard did not: a narrow channel where the monitor stand touches its
  corner joined it to the background, so no hole-filling could reach it.

So the routine is: generate, upscale, threshold, fill holes, then **look at the result over
the art** and patch what escaped. One object took one local fix.

Otherwise, paint it in any editor: white where the object is, black everywhere else, same
pixel size as the master. Either way, point the entry at the file:

```json
{ "name": "desk", "mask": "art/masks-manual/desk.png", "in_front_of": ["shell"] }
```

`segment.py` takes it **verbatim** — no matting, no hole filling — and never loads SAM for
that object. It is an authored input like `objects.json`: committed, and voided by a new
master. A rough starting mask can be rasterised from polygons and refined by hand, which is
much faster than tracing from nothing.

Reach for this when SAM has failed twice on the same object, not before. Thirteen of
fifteen objects here were one box each.

**see-through** does two things, and both matter:

1. **Enclosed holes are kept, not filled.** In a solid object a hole is a segmentation
   defect and its pixels belong to the object; left out, they stay nailed to the wall
   while the object moves. In a plant the identical hole is real background between the
   fronds. Same shape, same statistics — only you know which is which.
2. **The boundary is re-cut by an alpha matting model.** SAM decodes at 256×256 and
   upsamples, so a 3px frond is sub-pixel in its own output grid and comes back as part
   of a solid blob. Matting asks a different question — per-pixel coverage instead of
   in-or-out — and separates the fronds.

If a plant still looks like a cardboard cut-out in `_preview.png`, that is the flag being
off, not the model being bad.

## 3. Run the chain

```sh
P=tools/.venv/bin/python
M=art/build/masks

$P tools/depth.py      --color $S.jpg --out $B-depth.png
$P tools/depth_prep.py --color $S.jpg --depth $B-depth.png --out $B-depth8.png
$P tools/segment.py    --color $S.jpg --objects art/objects.json --out-dir $M
$P tools/depth_fix.py  --depth $B-depth8.png --objects art/objects.json \
  --masks $M --out $B-depth8-fixed.png --color $S.jpg --preview $B-depth-preview.png
$P tools/assign.py     --depth $B-depth8-fixed.png --objects art/objects.json \
  --masks $M --out-dir $M --color $S.jpg --preview $B-layers-preview.png
$P tools/inpaint.py    --color $S.jpg --depth $B-depth8-fixed.png \
  --masks $M --out-prefix $B --fill-dir art/fills --device mps
$P tools/export.py     --prefix $B --out-dir public/art \
  --master $S.jpg --picking-depth $B-depth8-fixed.png
```

Seven stages, one per tool, each reading files and writing files — no hidden state, so any
stage can be re-run alone once the ones above it have run. Stages 0 and 2 download model
weights on first use and are the slow ones; stage 5 is the slow one on every run
(`--device mps` on Apple silicon, `cuda` on a discrete GPU, else drop the flag).

| | writes | cost |
| --- | --- | --- |
| 0 `depth.py` | `$B-depth.png`, 16-bit disparity | Depth Anything V2-Large, ~1 min |
| 1 `depth_prep.py` | `$B-depth8.png`, rescaled + edge-aligned | numpy, seconds |
| 2 `segment.py` | `$M/<object>.png` | SAM 2.1 + ViTMatte, ~1 min |
| 3 `depth_fix.py` | `$B-depth8-fixed.png` | numpy, seconds |
| 4 `assign.py` | `$M/_layer{N}.png`, `$M/_layers.json` | numpy, seconds |
| 5 `inpaint.py` | `$B-layer{N}{,-depth,-hole}.png` | LaMa, ~23 crops, minutes |
| 6 `export.py` | `public/art/*.webp` — **the only output the site loads** | seconds |

## 4. Look at four pictures

Not the logs. Every mistake that has cost a whole pass was invisible in the logs and
obvious in these:

| Open this | Should look like |
| --- | --- |
| `$M/_preview.png` | each object outlined, nothing leaking onto walls or floor |
| `$B-depth-preview.png` | near things bright, far things dark, no flat cut-outs |
| `$B-layers-preview.png` | untinted shell, furniture one colour, things-standing-on-furniture another |
| `$B-shell-review.png` | **a believable empty room** |

## 5. Fill the holes properly

Stage 5 writes `$B-layer{N}-hole.png` — white is what an inpainter has to invent. LaMa runs
automatically, and it now **peels the objects off one at a time, nearest first**, each in a
crop with real room around it, rather than facing the whole hole at once. That is most of
the quality: the room corner, the window bars, the blue monitor glow, the lamp pools and
the sun patches all survive, none of which they did before.

**So look first, and make a fill only for what is actually wrong.** What LaMa still cannot
do is invent long straight structure across a wide hole — the skirting board behind the
cabinet is the standing case. Judge it in `$B-shell-review.png`, and judge it only in the
band beside each silhouette; the purple area is never revealed and its fill does not
matter. Do not widen `--halo` to chase soft object-shaped tone on a wall: that is the
object's cast shadow and it belongs there.

If a fill comes back as a smooth wash, read the `model px deep` figure the peel logs for
that object before touching anything else — that number, and not the mask, is what decides
whether LaMa returns a picture. `--fill-reach` (220) holds it there automatically; a wash
above it means the cap is off or set too high, and widening the mask or the crop will make
it worse, not better. See PIPELINE.md for the measurements.

```sh
# prompts EMPTY-0 (empty room) / EMPTY-1 (bare surfaces) in PROMPTS.md - attach $S.jpg and
# the hole mask, and EDIT: same camera, same lighting, same exposure, same pixel size.
# The generator returns a quarter of the master; upscale before saving.
mkdir -p art/fills
cp <generator output> art/fills/$NAME-layer0-fill.png     # full frame, same pixel size
```

Be warned that this is the path that has failed twice: asked to remove the furniture, a
generator removes the *light the furniture casts* along with it, and every object removed
is still in the composed scene in a nearer layer still lighting the surface behind it. The
plate comes back a genuinely empty room when what is wanted is this room with the objects
lifted off it.

Then re-run stages 5 and 6. Only the hole pixels are ever taken, so whatever the generator
does elsewhere is discarded and registration cannot drift.

Stage 5 also **anchors** the plate to the master: it reads the colour difference on a
ring of real master pixels just outside the hole and extends it inward as a smooth field,
so the fill meets the master with no step whatever the generator did. That is automatic
and it fixes *level* — the plate that removed the cabinet also removed the cabinet's
shadow, and came back 83 levels too bright on the floor behind it. It cannot fix
*drawing*: a membrane has no detail of its own, so an invented object, a shadow edge
missing from the middle of a large hole, or a wall painted in the wrong place is still
yours to **fix in the fill** — regenerate it, or patch that spot. Run with `--no-anchor`
to see the plate raw.

## 6. Wakes for the hotspots

The affordance for a clickable object is the object's own light coming up, baked from the
same SAM masks stage 3 already cut:

```sh
tools/.venv/bin/python tools/wake.py --masks art/build/masks --out-dir public/art \
  --wake monitor=monitor-left --wake window=window-glass
```

Only objects whose destination is actually built need one. The tool prints two rects per
hotspot and both go into `src/data/hotspots.ts`: `rect`, the mask's own bounding box, which
becomes the tap target; and `wakeRect`, where the cropped light sits in the frame. Pasting
both is what makes the tap target, the light and the camera's aim come from one mask rather
than three guesses.

The image is cropped to the light's own extent rather than kept full-frame. Full-frame was
simpler — `mask-size: cover` and no coordinates at all — but the light is `screen`-blended,
a blend mode takes an element off the compositor's fast path, and at full frame that meant
every frame of the hover fade repainted the whole room. The fade arrived in two or three
visible steps. Re-run this stage if the master is ever re-exported at a different crop.

This replaced a rim light traced on the silhouette. The rim looked right in a still and
failed in motion: it is a screen-space overlay over art that parallax keeps nudging, and a
hairline unglues from its edge with two or three pixels of drift. Soft light has no such
failure mode. Weights matter — the fill is deliberately weak (0.45) so the painted screen
keeps its sheen; at 0.85 the panel goes flat accent and the art underneath stops existing.

```sh
npm run dev     # then / for the hotspots and the push, /dev/room to tune the camera
```

## Starting over

Everything derived is regenerable:

```sh
rm -rf art/build public/art/*.webp
```

That is the whole of it, which is the point of the split: `art/build/` is *defined* as the
part a re-run reproduces. What survives is the four authored inputs listed in stage 1.

Re-running everything from a cold `art/build/` takes a few minutes and no decisions. If you
only want the cheap half, keep `$B-depth.png` and `$M/` and start at stage 1 — those two are
the model-weight stages.

## Re-running for a new master

Click points are normalised 0–1, so they survive a new master **at any resolution** as long
as the composition holds:

- **same room, re-rendered or upscaled** — change `NAME`, run stages 0–6, done.
- **furniture moved** — re-pick the objects that moved in `pick.py`, then run 0–6.
- **either way, delete `art/fills/*`.** A fill is pixel-registered to the master it was
  painted from and is useless against a different one.
